C++ Essentials

Before the algorithms themselves, it's worth being clear on what your C++ code is actually doing to memory. This section is the layer underneath every later section.

1.1 Value, Reference & Pointer Semantics

⚠ A Common Bug: Accidental Copies
Writing for (auto x : bigVector) instead of for (const auto& x : bigVector) copies every element on every iteration — silently turning an O(n) loop into an O(n · sizeof(T)) one. Default to const auto& in range-for loops unless you need a mutable copy.

1.3 Iterators & Common Algorithms

std::vector<int> v = {5, 3, 1, 4, 2}; std::sort(v.begin(), v.end()); // [1,2,3,4,5] O(n log n) auto it = std::find(v.begin(), v.end(), 4); // O(n) linear scan bool has = std::binary_search(v.begin(), v.end(), 4); // O(log n) — requires sorted range int total = std::accumulate(v.begin(), v.end(), 0); // fold; O(n) std::reverse(v.begin(), v.end()); // in place; O(n)
⚠ Iterator Invalidation
Erasing from a vector while iterating invalidates iterators from the erase point onward. The safe pattern uses the return value of erase:
for (auto it = v.begin(); it != v.end(); ) { if (*it % 2 == 0) it = v.erase(it); // erase returns the next valid iterator else ++it; }
For map/set, erasing an iterator only invalidates that iterator — others stay valid, which is why the same pattern is even more commonly seen there.

1.4 Memory, RAII & Smart Pointers

TypeOwnership modelOverheadUse when
unique_ptr<T>Exclusive — cannot be copied, only movedZero (same as raw pointer)Default smart pointer; sole owner of a resource
shared_ptr<T>Shared — reference-countedAtomic refcount + control blockMultiple owners genuinely need to share lifetime
weak_ptr<T>Non-owning observer of a shared_ptrSmallBreaking reference cycles (e.g. parent↔child trees)

RAII (Resource Acquisition Is Initialisation): tie a resource's lifetime to an object's scope, so it's released automatically — via the destructor — even if an exception is thrown. This is why smart pointers, std::lock_guard, and std::vector itself never leak: their destructors clean up.

✓ Stack vs Heap — What Matters
  • Stack: automatic storage, freed when scope ends, very fast (pointer bump), limited size (~1–8MB) — deep recursion overflows it.
  • Heap: new/malloc (or a container growing internally), lives until explicitly freed (or the owning smart pointer/container goes out of scope), slower, effectively unbounded.
A vector<int> v(1000000) declared locally puts the vector object (a few pointers) on the stack, but its data on the heap — a very common "gotcha" question.
2
Recursion

2.1 Base Case & Recursive Case

Every correct recursive function needs exactly two ingredients:

Anatomy of a Recursive Function
  1. Base case: the condition under which the function returns directly, without calling itself. This is what stops the recursion.
  2. Recursive case: the function calls itself on a smaller version of the problem, and combines that result into the answer for the current call.

"Recursive case" specifically means the branch that makes another call to the same function — every recursive function must guarantee that each such call moves strictly closer to a base case, or it never terminates.

2.2 Fibonacci: Naive, Memoized, Iterative

Naive Recursion

int fib(int n) { if (n <= 1) return n; // base case return fib(n - 1) + fib(n - 2); // recursive case }

Time complexity: $O(2^n)$. Each call spawns two more, and the same sub-problems (e.g. fib(3)) are recomputed exponentially many times — this recomputation is exactly what the next version fixes.

Memoized (Top-Down DP)

std::unordered_map<int,long long> memo; long long fibMemo(int n) { if (n <= 1) return n; if (memo.count(n)) return memo[n]; // cache hit — O(1) return memo[n] = fibMemo(n - 1) + fibMemo(n - 2); }

Time complexity: $O(n)$. Space complexity: $O(n)$ (the cache, plus O(n) call-stack depth). Each distinct n is computed exactly once.

Iterative (Bottom-Up, Constant Space)

long long fibIter(int n) { if (n <= 1) return n; long long prev = 0, curr = 1; for (int i = 2; i <= n; ++i) { long long next = prev + curr; prev = curr; curr = next; } return curr; }

Time complexity: $O(n)$. Space complexity: $O(1)$ — no recursion, no cache, just two rolling variables. This is the version to reach for in production; the memoized version is the one to reach for when the recursive structure of the problem is less obvious (most DP problems).

💡 The General Lesson
Naive recursion → memoization → iteration is the standard three-step refinement path for any overlapping-subproblem recursion, not just Fibonacci: identify exponential blowup from repeated subproblems, cache to fix it, then ask whether the recursion can be "unrolled" into an iterative loop to drop the space cost.

2.3 The Call Stack & Tail Recursion

Every recursive call pushes a new stack frame (return address, parameters, locals). Depth $n$ recursion uses $O(n)$ stack space — for fib(100000) called naively, this overflows the stack (typically ~1MB, a few hundred thousand frames) long before the $O(2^n)$ time cost even becomes the bottleneck.

Tail Recursion
A call is a tail call if it is the very last action in the function — nothing happens after it returns. fibIter's loop body has no recursion at all, but a tail-recursive rewrite of Fibonacci would look like:
long long fibTail(int n, long long a = 0, long long b = 1) { if (n == 0) return a; return fibTail(n - 1, b, a + b); // nothing left to do after this call returns }
⚠ C++ Does Not Guarantee Tail-Call Optimisation
Unlike Scheme or some functional languages, the C++ standard does not require compilers to convert tail calls into loops — -O2/-O3 often will, but it is not portable or guaranteed, especially in debug builds. Never rely on tail recursion for stack safety — if depth can be large, write the explicit loop (as in fibIter).

2.4 Reversing a String Recursively

std::string reverseStr(std::string s) { if (s.size() <= 1) return s; // base case return reverseStr(s.substr(1)) + s[0]; // recursive case }

Each call peels off the first character and appends it after the reversed remainder. This is clean but $O(n^2)$ due to repeated substr copies. The in-place two-pointer version is the one to actually use:

void reverseInPlace(std::string& s, int lo, int hi) { if (lo >= hi) return; // base case std::swap(s[lo], s[hi]); reverseInPlace(s, lo + 1, hi - 1); // recursive case } // O(n) time, O(n) recursion-stack space (O(1) if written as a while-loop instead)

Searching

3.1 Linear Search

int linearSearch(const std::vector<int>& v, int target) { for (int i = 0; i < (int)v.size(); ++i) if (v[i] == target) return i; return -1; } // O(n) time, O(1) space — the only option on unsorted data

3.2 Binary Search — Iterative & Recursive

Requires the range to be sorted. At each step, halve the search space by comparing the midpoint to the target.

// Iterative — the version to default to (no stack-depth concerns) int binarySearch(const std::vector<int>& v, int target) { int lo = 0, hi = (int)v.size() - 1; while (lo <= hi) { int mid = lo + (hi - lo) / 2; // avoids (lo+hi) overflow if (v[mid] == target) return mid; else if (v[mid] < target) lo = mid + 1; else hi = mid - 1; } return -1; }
⚠ The Classic Overflow Bug
int mid = (lo + hi) / 2; overflows a 32-bit int when lo + hi exceeds ~2.1 billion — a real risk with large arrays. mid = lo + (hi - lo) / 2 is algebraically identical but never overflows. It's the classic edge case worth checking any time you write binary search.
// Recursive — equivalent, but costs O(log n) stack frames int binarySearchRec(const std::vector<int>& v, int target, int lo, int hi) { if (lo > hi) return -1; // base case: not found int mid = lo + (hi - lo) / 2; if (v[mid] == target) return mid; // base case: found if (v[mid] < target) return binarySearchRec(v, target, mid + 1, hi); return binarySearchRec(v, target, lo, mid - 1); } // O(log n) time either way; O(log n) space recursive vs O(1) iterative

3.3 lower_bound / upper_bound

The STL versions generalise binary search to find boundaries rather than exact matches — essential for counting occurrences and range queries.

FunctionReturns iterator to
lower_bound(first, last, x)First element $\geq x$ (insertion point that keeps order, before duplicates of x)
upper_bound(first, last, x)First element $> x$ (insertion point after all duplicates of x)
std::vector<int> v = {1, 3, 3, 3, 5, 7}; auto lo = std::lower_bound(v.begin(), v.end(), 3); // points to first 3 (index 1) auto hi = std::upper_bound(v.begin(), v.end(), 3); // points to 5 (index 4) int countOf3 = hi - lo; // = 3, in O(log n)

3.4 Binary Search on the Answer

A very common pattern: the array itself needn't be sorted — instead, binary search over the space of candidate answers, using a monotonic feasibility check (works for values $\leq x^*$, fails above it, or vice versa).

📋 Pattern: Minimise the Maximum
"Split an array into k subarrays to minimise the largest subarray sum." Binary search over the candidate answer (the max subarray sum), from max(array) to sum(array). For each candidate mid, greedily check in $O(n)$ whether you can split the array into $\leq k$ pieces each summing to $\leq$ mid. Feasibility is monotone in mid, so binary search finds the smallest feasible value in $O(n \log(\text{sum}))$.
bool feasible(const std::vector<int>& a, long long cap, int k) { int pieces = 1; long long curr = 0; for (int x : a) { if (curr + x > cap) { ++pieces; curr = x; } // start a new piece else curr += x; } return pieces <= k; } long long minimiseMax(const std::vector<int>& a, int k) { long long lo = *std::max_element(a.begin(), a.end()); long long hi = std::accumulate(a.begin(), a.end(), 0LL); while (lo < hi) { long long mid = lo + (hi - lo) / 2; if (feasible(a, mid, k)) hi = mid; // try to do better else lo = mid + 1; } return lo; }

4.3 Quicksort From Scratch

int partition(std::vector<int>& v, int lo, int hi) { int pivot = v[hi]; // last element as pivot int i = lo - 1; for (int j = lo; j < hi; ++j) if (v[j] < pivot) std::swap(v[++i], v[j]); std::swap(v[i + 1], v[hi]); return i + 1; // final pivot position } void quicksort(std::vector<int>& v, int lo, int hi) { if (lo >= hi) return; // base case int p = partition(v, lo, hi); quicksort(v, lo, p - 1); quicksort(v, p + 1, hi); }
⚠ Worst Case: Already-Sorted Input
With last-element pivoting, an already-sorted (or reverse-sorted) array degrades every partition to size $n-1$ vs $0$, giving $O(n^2)$ time and $O(n)$ recursion depth (risking stack overflow). Fixes: pick a random pivot, or median-of-three (first/middle/last), which make the worst case exponentially unlikely.

4.4 Mergesort From Scratch

void merge(std::vector<int>& v, int lo, int mid, int hi) { std::vector<int> tmp; int i = lo, j = mid + 1; while (i <= mid && j <= hi) tmp.push_back(v[i] <= v[j] ? v[i++] : v[j++]); // <= keeps it stable while (i <= mid) tmp.push_back(v[i++]); while (j <= hi) tmp.push_back(v[j++]); std::copy(tmp.begin(), tmp.end(), v.begin() + lo); } void mergesort(std::vector<int>& v, int lo, int hi) { if (lo >= hi) return; // base case int mid = lo + (hi - lo) / 2; mergesort(v, lo, mid); mergesort(v, mid + 1, hi); merge(v, lo, mid, hi); } // Recurrence T(n) = 2T(n/2) + O(n) → O(n log n) always, O(n) extra space
💡 Quicksort vs Mergesort — The Short Answer
Quicksort sorts in place ($O(\log n)$ stack space) and has better cache locality, so it's typically faster in practice — this is why std::sort is quicksort-based. Mergesort guarantees $O(n\log n)$ worst case and is stable, at the cost of $O(n)$ extra memory — this is why std::stable_sort and external sorts (data too big for RAM) use it.

Trees & Traversals

5.1 The Binary Tree Node

struct TreeNode { int val; TreeNode* left; TreeNode* right; TreeNode(int x) : val(x), left(nullptr), right(nullptr) {} };

5.2 In-Order, Pre-Order, Post-Order

TraversalOrderTypical use
In-orderleft → node → rightOn a BST, visits values in sorted order
Pre-ordernode → left → rightCopying/serialising a tree (root first)
Post-orderleft → right → nodeDeleting a tree; evaluating expression trees (operands before operator)
void inOrder(TreeNode* node, std::vector<int>& out) { if (!node) return; // base case inOrder(node->left, out); out.push_back(node->val); inOrder(node->right, out); } void preOrder(TreeNode* node, std::vector<int>& out) { if (!node) return; out.push_back(node->val); preOrder(node->left, out); preOrder(node->right, out); } void postOrder(TreeNode* node, std::vector<int>& out) { if (!node) return; postOrder(node->left, out); postOrder(node->right, out); out.push_back(node->val); } // All three: O(n) time (visit every node once), O(h) recursion stack, h = tree height

5.3 Iterative Traversal With an Explicit Stack

Recursive traversal uses the call stack implicitly; writing the iterative version is a good way to check you understand what that call stack is actually doing.

std::vector<int> inOrderIter(TreeNode* root) { std::vector<int> out; std::stack<TreeNode*> stk; TreeNode* curr = root; while (curr || !stk.empty()) { while (curr) { // walk all the way left, pushing as we go stk.push(curr); curr = curr->left; } curr = stk.top(); stk.pop(); out.push_back(curr->val); curr = curr->right; } return out; } // O(n) time, O(h) space — same complexity as recursion, but the stack is explicit

5.4 Level-Order (BFS) Traversal

std::vector<std::vector<int>> levelOrder(TreeNode* root) { std::vector<std::vector<int>> levels; if (!root) return levels; std::queue<TreeNode*> q; q.push(root); while (!q.empty()) { int sz = q.size(); // snapshot: nodes at the current level std::vector<int> level; for (int i = 0; i < sz; ++i) { TreeNode* node = q.front(); q.pop(); level.push_back(node->val); if (node->left) q.push(node->left); if (node->right) q.push(node->right); } levels.push_back(level); } return levels; } // O(n) time, O(w) space, w = maximum width of the tree

5.5 BST Insert / Search / Delete

TreeNode* bstInsert(TreeNode* node, int val) { if (!node) return new TreeNode(val); // base case: found the insertion spot if (val < node->val) node->left = bstInsert(node->left, val); else node->right = bstInsert(node->right, val); return node; } bool bstSearch(TreeNode* node, int val) { if (!node) return false; if (node->val == val) return true; return val < node->val ? bstSearch(node->left, val) : bstSearch(node->right, val); } // O(h) time — O(log n) if balanced, degrades to O(n) on a skewed/linear tree
⚠ A Plain BST Is Not Worst-Case Efficient
Inserting already-sorted data into a plain BST produces a degenerate linked list — $O(n)$ operations, not $O(\log n)$. This is exactly why std::map/std::set use a self-balancing red-black tree internally: it re-balances on every insert/erase to guarantee $O(\log n)$ regardless of input order. It's worth knowing this trade-off and being able to name the failure mode of a naive BST, even if you rarely implement AVL/red-black rebalancing from scratch.

6.2 BFS & DFS Implementation

// BFS — shortest path in an UNWEIGHTED graph std::vector<int> bfs(int src, int n, const std::vector<std::vector<int>>& adj) { std::vector<int> dist(n, -1); std::queue<int> q; dist[src] = 0; q.push(src); while (!q.empty()) { int u = q.front(); q.pop(); for (int v : adj[u]) if (dist[v] == -1) { dist[v] = dist[u] + 1; q.push(v); } } return dist; // dist[v] = fewest edges from src to v, or -1 if unreachable } // DFS — recursive; reachability, cycle detection, topological sort void dfs(int u, const std::vector<std::vector<int>>& adj, std::vector<bool>& visited) { visited[u] = true; for (int v : adj[u]) if (!visited[v]) dfs(v, adj, visited); } // Both: O(V + E) time, O(V) space
✓ BFS vs DFS — When to Reach for Which
BFS when you need the shortest path in an unweighted graph, or level-by-level structure. DFS when you just need reachability/connectivity, cycle detection, or a topological order — and DFS is usually the simpler code (recursion vs an explicit queue).

6.3 Dijkstra's Algorithm

Shortest paths from a single source in a weighted graph with non-negative edge weights. Greedily extends the shortest-known frontier using a min-heap.

std::vector<long long> dijkstra(int src, int n, const std::vector<std::vector<std::pair<int,int>>>& adj) { // adj[u] = {(v, weight), ...} std::vector<long long> dist(n, std::numeric_limits<long long>::max()); std::priority_queue<std::pair<long long,int>, std::vector<std::pair<long long,int>>, std::greater<>> pq; // min-heap by distance dist[src] = 0; pq.push({0, src}); while (!pq.empty()) { auto [d, u] = pq.top(); pq.pop(); if (d > dist[u]) continue; // stale entry — a shorter path was already found for (auto [v, w] : adj[u]) { if (dist[u] + w < dist[v]) { dist[v] = dist[u] + w; pq.push({dist[v], v}); } } } return dist; } // O((V + E) log V) with a binary heap
⚠ Dijkstra Fails on Negative Edge Weights
The greedy "once popped, finalised" argument relies on all edge weights being $\geq 0$. With a negative edge, a shorter path could still be discovered after a node is finalised, and Dijkstra will return a wrong (too-large) distance without any error or warning. Use Bellman-Ford when negative weights are possible.

Minimum Spanning Tree

A minimum spanning tree (MST) connects all $V$ vertices of a weighted, undirected, connected graph using exactly $V-1$ edges, at minimum total weight. Two classic greedy algorithms — Kruskal's needs Union-Find; Prim's needs a priority queue.

7.1 Union-Find (Disjoint Set Union)

Maintains a partition of elements into disjoint sets, supporting near-$O(1)$ "are these connected?" and "merge these two sets" — the engine behind Kruskal's algorithm and cycle detection in undirected graphs.

struct DSU { std::vector<int> parent, rank_; DSU(int n) : parent(n), rank_(n, 0) { std::iota(parent.begin(), parent.end(), 0); // each node its own parent initially } int find(int x) { if (parent[x] != x) parent[x] = find(parent[x]); // path compression return parent[x]; } bool unite(int a, int b) { a = find(a); b = find(b); if (a == b) return false; // already connected — would form a cycle if (rank_[a] < rank_[b]) std::swap(a, b); parent[b] = a; // union by rank if (rank_[a] == rank_[b]) rank_[a]++; return true; } }; // With both optimisations: amortised O(α(n)) per op — α = inverse Ackermann, effectively constant

7.2 Kruskal's Algorithm

Kruskal — Sort Edges, Greedily Add if No Cycle
  1. Sort all edges by weight, ascending.
  2. For each edge $(u,v,w)$ in order: if $u$ and $v$ are in different DSU components, add the edge to the MST and union them.
  3. Stop once $V-1$ edges have been added.
struct Edge { int u, v, w; }; long long kruskal(int n, std::vector<Edge> edges) { std::sort(edges.begin(), edges.end(), [](const Edge& a, const Edge& b) { return a.w < b.w; }); DSU dsu(n); long long total = 0; int used = 0; for (auto& e : edges) { if (dsu.unite(e.u, e.v)) { // returns false if it would create a cycle total += e.w; if (++used == n - 1) break; } } return total; } // O(E log E) — dominated by the sort

7.3 Prim's Algorithm

Prim — Grow One Tree From a Start Vertex
Maintain a frontier of edges leaving the current tree in a min-heap; repeatedly pull the cheapest edge that reaches a new vertex.
long long prim(int n, const std::vector<std::vector<std::pair<int,int>>>& adj) { // adj[u] = {(v,w)} std::vector<bool> inMST(n, false); std::priority_queue<std::pair<int,int>, std::vector<std::pair<int,int>>, std::greater<>> pq; // (weight, vertex), min-heap pq.push({0, 0}); long long total = 0; while (!pq.empty()) { auto [w, u] = pq.top(); pq.pop(); if (inMST[u]) continue; // stale entry inMST[u] = true; total += w; for (auto [v, vw] : adj[u]) if (!inMST[v]) pq.push({vw, v}); } return total; } // O(E log V) with a binary heap — same asymptotic class as Kruskal
💡 Kruskal vs Prim — When to Reach for Which
Kruskal is the natural choice for a sparse edge list you can sort once — and reuses the DSU machinery you likely already need for cycle detection elsewhere. Prim is a better fit for a dense graph given as an adjacency matrix/list from a fixed start vertex, and feels structurally close to Dijkstra (both grow a frontier from a min-heap) — the one-line difference is that Prim relaxes by edge weight, while Dijkstra relaxes by cumulative distance.

8.1 The DP Recipe in C++

Five Steps, Every Time
  1. Define the state: what does dp[i] (or dp[i][j]) mean, in words?
  2. Write the recurrence: express the state in terms of smaller states.
  3. Identify base cases.
  4. Choose direction: top-down with an unordered_map/vector cache, or bottom-up filling a table in order.
  5. Extract the answer from the state(s) that represent the full problem.

8.2 0/1 Knapsack

State: dp[i][c] = max value using the first i items with capacity c.

int knapsack(const std::vector<int>& wt, const std::vector<int>& val, int W) { int n = wt.size(); std::vector<int> dp(W + 1, 0); // rolling 1D array — capacity dimension only for (int i = 0; i < n; ++i) for (int c = W; c >= wt[i]; --c) // iterate DOWN — each item used at most once dp[c] = std::max(dp[c], val[i] + dp[c - wt[i]]); return dp[W]; } // O(n * W) time, O(W) space
⚠ Loop Direction Is the Whole Trick
Iterating the capacity loop downward ensures dp[c - wt[i]] still refers to the value before item i was considered — giving 0/1 (each item used once). Iterating upward instead turns this into the unbounded knapsack (unlimited reuse of each item) — a one-character change with a completely different meaning, and an easy bug to introduce without noticing.

8.3 Longest Common Subsequence

State: dp[i][j] = LCS length of s[0..i) and t[0..j).

int lcs(const std::string& s, const std::string& t) { int m = s.size(), n = t.size(); std::vector<std::vector<int>> dp(m + 1, std::vector<int>(n + 1, 0)); for (int i = 1; i <= m; ++i) for (int j = 1; j <= n; ++j) dp[i][j] = (s[i-1] == t[j-1]) ? dp[i-1][j-1] + 1 : std::max(dp[i-1][j], dp[i][j-1]); return dp[m][n]; } // O(mn) time and space; space reducible to O(min(m,n)) with a rolling row

8.4 Coin Change (Fewest Coins)

State: dp[a] = fewest coins summing to amount a.

int coinChange(const std::vector<int>& coins, int amount) { std::vector<int> dp(amount + 1, INT_MAX); dp[0] = 0; for (int a = 1; a <= amount; ++a) for (int c : coins) if (c <= a && dp[a - c] != INT_MAX) dp[a] = std::min(dp[a], dp[a - c] + 1); return dp[amount] == INT_MAX ? -1 : dp[amount]; } // O(amount * |coins|) time, O(amount) space — coins loop INSIDE: unlimited reuse per coin

8.5 Longest Increasing Subsequence

// O(n^2) DP: dp[i] = length of the longest increasing subsequence ending at i int lisSlow(const std::vector<int>& a) { int n = a.size(); std::vector<int> dp(n, 1); int best = n ? 1 : 0; for (int i = 0; i < n; ++i) { for (int j = 0; j < i; ++j) if (a[j] < a[i]) dp[i] = std::max(dp[i], dp[j] + 1); best = std::max(best, dp[i]); } return best; } // O(n log n): maintain the smallest possible tail for each achievable LIS length int lisFast(const std::vector<int>& a) { std::vector<int> tails; // tails[k] = smallest tail of an increasing subseq of length k+1 for (int x : a) { auto it = std::lower_bound(tails.begin(), tails.end(), x); if (it == tails.end()) tails.push_back(x); // extends the longest subsequence so far else *it = x; // improves (lowers) an existing tail } return tails.size(); }
💡 Why lisFast Works
tails is always sorted, and its length — not its contents — is the LIS length; each entry is the smallest tail achievable for that subsequence length, which maximises future extensibility. Binary-searching for where x belongs and overwriting is what compresses $O(n^2)$ into $O(n\log n)$ — a pattern (greedy + binary search replacing an $O(n)$ inner scan) worth recognising beyond just LIS.
