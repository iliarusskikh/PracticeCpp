Binary Protocol { TICK + HEARTBEAT }

Phase 1: replace the text echo with fixed-size packed messages. Scope is MsgType::TICK and MsgType::HEARTBEAT only — no ORDER.

01

Why binary over text echo

The baseline server/client echo lines of text. That is fine for proving sockets work; it is a poor wire format for market data.

  • Parsing cost — scanning for \n, splitting tokens, atoi/stod on every tick. Binary copies bytes into a struct (after endian fixups).
  • Structure — fields have fixed offsets and types. No ambiguity about separators, floats-as-strings, or trailing whitespace.
  • Interview story — “We moved from line-oriented echo to a binary feed so size and layout are known at compile time; the hard part is framing on a TCP stream and endianness, not string parsing.”
02

Fixed-size vs length-prefixed

SchemeIdeaTrade-off
Fixed-size Every message of a type is exactly sizeof(T) bytes Simple read loop; no variable payload; size changes only when you change the struct
Length-prefixed Header with length (or type+length), then N payload bytes Needed for strings / variable books; more framing states

We choose fixed-size for both TICK and HEARTBEAT. Discriminate with a leading uint8_t msg_type, then read the remaining bytes for that type (or always read the larger type after peeking the first byte — implementation detail).

03

#pragma pack / alignment

Compilers insert padding so members land on natural alignments (e.g. uint32_t on a 4-byte boundary). Padding makes sizeof larger and layout compiler-dependent — bad on the wire.

protocol.hpp
#pragma pack(push, 1)   // no padding between members
struct TickMsg { /* ... */ };
struct HeartbeatMsg { /* ... */ };
#pragma pack(pop)       // restore previous packing

Packed structs are for serialization. Prefer converting field-by-field with hton*/ntoh* rather than memcpying a host-endian struct straight to the socket without conversion.

04

Endianness

Network byte order is big-endian. Apple Silicon and x86 hosts are little-endian — multi-byte integers must be converted on send and again on receive.

WidthHost → networkNetwork → host
16-bithtonsntohs
32-bithtonlntohl
64-bitcustom / htobe64 where availablematching be64toh / helper

uint8_t msg_type needs no swap. Convert symbol_id, price, timestamp_ns, volume (and heartbeat timestamp) explicitly.

Gotcha

Skipping ntoh* on receive “works” only if both ends are the same endianness and you never test otherwise. Write the conversions anyway — that is the interview-correct habit.

05

Partial reads — TCP is a stream

TCP delivers a byte stream, not messages. One send of 25 bytes can arrive as two recvs of 10 and 15 — or one recv that contains two full messages plus a fragment.

recv_exact.cpp
bool recv_exact(int fd, void* buf, size_t n) {
    auto* p = static_cast<char*>(buf);
    size_t got = 0;
    while (got < n) {
        ssize_t r = recv(fd, p + got, n - got, 0);
        if (r == 0) return false;          // peer closed
        if (r < 0) {
            if (errno == EINTR) continue;
            return false;                  // or handle EAGAIN when non-blocking
        }
        got += static_cast<size_t>(r);
    }
    return true;
}
// usage: TickMsg m; recv_exact(fd, &m, sizeof(m));

Always accumulate until you have sizeof(msg) (or the fixed size for the type you are reading). Never assume one recv equals one message.

06

Message structs (PLAN.md)

protocol.hpp (sketch)
enum class MsgType : uint8_t { TICK = 1, HEARTBEAT = 2 };

#pragma pack(push, 1)
struct TickMsg {
    uint8_t  msg_type;      // MsgType::TICK
    uint32_t symbol_id;
    int64_t  price;         // scaled integer (e.g. micros)
    uint64_t timestamp_ns;  // or steady-clock ticks
    uint32_t volume;
};
struct HeartbeatMsg {
    uint8_t  msg_type;      // MsgType::HEARTBEAT
    uint64_t timestamp_ns;
};
#pragma pack(pop)

// sizeof(TickMsg) == 1+4+8+8+4 = 25
// sizeof(HeartbeatMsg) == 1+8 = 9

Serialize helpers: set fields in host order → apply hton* → send exactly sizeof bytes. Deserialize: recv_exact → ntoh* → use.

07

Project decision

Decision

Fixed-size packed binary with two message types only: TICK and HEARTBEAT. No ORDER/ACK, no length-prefixed blobs, no JSON. Prices are scaled integers on the wire. All multi-byte fields use network byte order; receivers loop until a full message is buffered.

08

Common pitfalls

✕

Forgetting ntoh* on receive

Prices, IDs, and timestamps look “almost right” on little-endian hosts talking to themselves — then break on a different machine or when you actually inspect byte order.

✕

Assuming one recv = one message

TCP is a stream. Partial and coalesced reads are normal; without a read-until-full loop (or an explicit buffer), you desync the stream and every later message is garbage.

✕

Sending without packing

Default alignment padding means sizeof and field offsets disagree between compilers/ABIs. Use #pragma pack(push, 1) (or serialize field-by-field into a byte buffer).
