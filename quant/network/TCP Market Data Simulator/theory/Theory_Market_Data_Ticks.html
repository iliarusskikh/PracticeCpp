Market Data Ticks { Phase 4 synthetic generator }

Not a real exchange. The server invents fixed-size binary ticks so you can practice protocol, poll(), and client consumption — not market microstructure.

01

What a tick is here

In this project a tick is one last-trade-style update: enough fields to exercise the wire format and fan-out, nothing more.

FieldType (sketch)Role
symbol_iduint32_tWhich instrument (numeric id, not a string on the wire)
priceint64_tScaled integer (e.g. micros) — see below
volumeuint32_tSynthetic size for the update
timestamp_nsuint64_tServer stamp (steady-clock ticks or wall ns)

Plus a msg_type byte so the stream can carry TICK and later HEARTBEAT. Layout lives in the binary-protocol note / PLAN.md.

02

Why integer / scaled prices

Put int64_t on the wire (price × 10n), not double.

  • Determinism — same seed → same integer path. Float rounding differs by platform/math lib.
  • Endianness is boring — htonl/htobe64-style swaps on integers are well-defined. IEEE floats have their own byte layout; shipping them invites subtle “it worked on my Mac” bugs.
  • Interview line — “Money and prices are fixed-point in production systems; floating point is for analytics, not the wire or the ledger.”
Talking point

Scaled ints keep the protocol simple, exact, and portable. Display as decimal only at the edge (log / UI).

03

Random-walk model

Per symbol, keep a current mid. Each tick:

generator sketch
// price is already scaled (e.g. micros)
price += rng_delta();          // small signed step, e.g. [-k, +k]
if (price < floor) price = floor;
if (price > ceiling) price = ceiling;
// or: start from a seeded mid and clamp to a band

Volume can be a small random int. Timestamp = now. This is a toy path — no drift calibration, no vol surface, no order-flow imbalance.

04

Symbols & tick rate (planned)

Phase 1.2 / 4.1: a simple key=value file drives host, port, symbol list, and tick rate. Sane defaults if keys are missing.

config.example
host=127.0.0.1
port=9000
symbols=1,2,3
tick_rate_hz=100

Not implemented yet — planned so you can demo multi-symbol feed without recompiling.

05

Generate & broadcast

The server owns the generator. On each tick interval it builds a TickMsg, then the Phase 3 poll() loop fans it out to every connected client (write when writable; buffer or drop policy as you implement).

  • One generator → N sockets (broadcast), not one stream per client with different prices.
  • Clients only parse/log; they do not send orders.
06

Honest scope

Be clear in interviews

This is a learning infrastructure simulator: sockets, binary framing, multi-client I/O, heartbeats. It is not market-microstructure research, not a realistic LOB, and not a claim that the prices mean anything economically.

07

Project decision

Decision

Synthetic last-tick feed only — fixed fields, scaled ints, random walk, config-driven symbols/rate, server-side generation + poll broadcast. No ORDER/ACK, no book, no matching engine. Goal: a CV-ready TCP market-data story, not a mini exchange.
